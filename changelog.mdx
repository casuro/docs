<Update label="May 25, 2026" description="V0.35.0">
- 📱 **SMS opt-in consent on job applications** — candidates applying through `jobs.casuro.ai` now see an explicit, unchecked, TCPA-style consent checkbox under the phone field with the carrier-required disclosure ("recurring automated text messages from Casuro... Message frequency varies. Message and data rates may apply. Reply HELP for help or STOP to unsubscribe. Consent is not a condition of applying."). The checkbox only renders when the job's application form has a phone field; submission is never blocked by an unchecked box. Consent state, server-side timestamp, and source are persisted on `jobApplications` (new optional `smsConsent` / `smsConsentAt` / `smsConsentSource` columns) so any future SMS sender can gate on `smsConsent === true`. Sets the foundation for sending candidates assessment invitations, interview reminders, deadlines, and next-step updates via SMS
- 🎨 **Brand-colored buttons auto-pick readable text color** — every button on `jobs.casuro.ai` that paints itself with an org's brand color (application Submit, "View open roles" on closed jobs, the three voice-agent CTAs) now derives its text color from the background luminance. Light brand colors get `casuro-dark` text; dark brand colors keep white. Removes the failure mode where a yellow or pastel brand color rendered with invisible white text
- 📄 **Privacy Policy + Terms of Service hardened for A2P 10DLC carrier approval** — both pages now carry the disclosures that carriers and TCR check for during SMS campaign vetting: dedicated SMS Communications section (Privacy §9, Terms §8) with sender-specific opt-in, message categories, frequency, rates, STOP/HELP, no-sharing clause, and SMS consent-record retention. Privacy adds a deep-link anchor at `/privacy#sms-communications` for the campaign filing. Terms §12 Governing Law replaces the `[Your Jurisdiction]` placeholder with California / Los Angeles County. Form-disclosure wording and policy wording match verbatim — closes the most common "conflicting information" rejection reason
</Update>

<Update label="May 15, 2026" description="V0.33.9">
- 📊 **Activity timeline on the Manage modal** — replaces the prior Profile tab with a per-candidate timeline. For a360 challenges, one event per question with status (Answered / Silent / Disconnected / In progress / Not started), persona, recording duration, transcript preview, attempt count, and a recording affordance — surfaces zombie ai_calls (`status: "active"` after agent disconnect), silent recordings (transcriptionConfidence 0), and stuck candidates inline. For case_study and everything else, the same timeline rendered from `challenge.steps` (case / interview / evaluation / decision), surfacing failed evaluation steps with their inline error message. Vertical spine + tabular timestamps + uppercase ASKED / SAID / META micro-labels so the events read like a chronological log
- 🪟 **Click candidate cards or rows to open the full detail in a modal** — pipeline board (`/jobs/[id]/pipeline`) and the All Applications table (`/applications`) no longer route to `/applications/[id]`. Both surfaces open the same body inside a 4xl modal overlay, so staff stay in the list / kanban context while triaging. The standalone route still works for direct links and bookmarks. Behind the scenes the body was extracted to `src/components/application/` so it can be embedded anywhere
- ✅ **A360 evaluation retries actually engage on transcript races** — followup to V0.33.2. The action's outer `catch` was swallowing the transcription-readiness throw, so `step.runAction`'s 5 × exp-backoff (~45s) retry budget never fired and the workflow failed in ~80ms when an AI-call's transcript hadn't quite landed (LiveKit egress → STT → saveTranscript typically takes 5–15s). Introduced a `TranscriptionNotReadyError` sentinel and re-raise it from the catch so the retry does what the original V0.33.2 commit message claimed. Also moved the workflow's `✅ AI evaluation complete` log inside the success branch so failure runs no longer print a misleading success line
</Update>
